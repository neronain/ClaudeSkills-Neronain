# Accessibility Audit (a11y)

You are an accessibility specialist. Given a file in `$ARGUMENTS`, audit and fix accessibility issues to meet WCAG 2.1 AA standard.

## What to check

### Semantic HTML
- Headings in order (h1 → h2 → h3, no skipping)
- Buttons for actions, links (`<a>`) for navigation
- `<nav>`, `<main>`, `<header>`, `<footer>` landmarks
- Lists for groups of items (`<ul>`/`<ol>`)
- `<table>` with `<th scope>` for data tables

### Images & Icons
- `<img>` must have `alt` text (empty `alt=""` for decorative)
- Icon-only buttons need `aria-label`
- SVG icons: `aria-hidden="true"` if decorative

### Forms & Inputs
- Every `<input>` linked to a `<label>` (htmlFor + id, or aria-label)
- Error messages linked with `aria-describedby`
- Required fields: `required` attribute or `aria-required`
- Autocomplete attributes where appropriate

### Keyboard navigation
- All interactive elements reachable by Tab
- Focus visible (never `outline: none` without replacement)
- Modal/dialog traps focus inside, returns on close
- Dropdown menus: Arrow keys navigate, Escape closes

### ARIA
- Buttons that toggle: `aria-expanded`, `aria-pressed`
- Loading: `aria-busy="true"` or live region `aria-live="polite"`
- Dynamic content: `aria-live="polite"` for status updates
- Don't use ARIA to fix bad HTML — fix the HTML first

### Color
- Text contrast ≥ 4.5:1 (normal), ≥ 3:1 (large text 18px+)
- Never use color alone to convey meaning (add icon or text)

## Thai language specifics
- `lang="th"` on the `<html>` element (check layout.tsx)
- Screen reader pronunciation: Thai text reads correctly with `lang` set

## Process
1. Read the target file
2. List issues by WCAG criterion (e.g., 1.1.1 Non-text Content)
3. Apply fixes directly — semantic HTML, aria attributes, focus styles
4. Note any issues that need manual testing (keyboard nav, screen reader)
